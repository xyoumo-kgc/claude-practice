# FX_Fusion_EA — FUSION-CORE v1.0 の MT5 EA（説明書）

## 概要

「賢人のデイトレード」と「100億円トレーダー（4つの鉄板エントリーパターン）」の考え方を突き合わせ、
反証検証（根拠・固有性・反例の3視点）を経ても残った共通点だけを骨格にした融合FXシステム
**FUSION-CORE v1.0** を、MT5 の EA（Expert Advisor）にしたものです。

仕様は [`fusion/SPEC.md`](../fusion/SPEC.md)（凍結）、売買判定の正解は Python 参照実装
[`fusion/strategy.py`](../fusion/strategy.py)（約定モデルは `fusion/broker.py`、スイングの定義は `fusion/indicators.py`）です。
この EA は、その判定部を MQL5 に移植し、MT5 での監視・通知・パネル表示・任意の自動売買をつけたものです。
2人の考え方のどこが共通でどこが違うかは [`fusion/THEORY.md`](../fusion/THEORY.md) にあります。

> 4時間足レベルの上昇（下降）構造の中で、押し（戻り）が 4H MA（1時間足の SMA80）に届き、その 4H MA が逆向きでないときに、
> 1時間足で「安値切上げを保ったまま戻り高値を上抜ける」瞬間を逆指値で取る。損切りは切上げ安値の外。
> 出口は「4H レベルの新しい押し安値が確定するたびに損切りを引き上げる」と「週末・休場前の全決済」だけ。
> 分割・建値移動・固定利確・時間決済はしない。

- 判定は **H1 の確定足だけ**で行います。4時間足・日足は、期間を換算した移動平均（SMA80＝4H の 20MA、SMA480＝日足の 20MA）と
  スイングの深さ（12本＝4H レベル、72本＝日足レベル）で表すので、上位足の未確定足を見る余地がありません。
- 既定は **シグナル通知＋パネル表示**です。建玉と約定は `fusion/broker.py` と同じ仮想ブローカーで追うので、
  通知の内容と Python の取引一覧が一致します。
- 自動売買は任意で、**既定 OFF** です（有効にする条件は後述）。

### 2人の共通点のどこを使っているか

分類の意味（`fusion/THEORY.md` と同じ）: **本質的**＝考え方だけでなく運用手順まで両者本人の発信で一致 ／
**部分的**＝考え方は共通だが運用に差があるか片側が未確認 ／ **一般論**＝両者に当てはまるが、ダウ理論系の順張りトレーダーなら
誰でも言う内容（2人固有ではないという意味で、誤りという意味ではない）。

| ID | 共通点 | 分類 | この EA での位置 |
|---|---|---|---|
| C02 | 4時間足レベルの押し目・戻り目（4H MA 付近）を、1時間足のダウ転換確定（安値切上げ＋戻り高値更新）で順張りする | **本質的**（唯一） | 中核。G1（4H ダウ構造）・G2（押しが SMA80 に到達）・1H 転換トリガー（戻り高値の直上の逆指値） |

### 優位性の状態（必読）

- **最終検証（未接触データで1回だけ）は不合格でした**（[`fusion/RESULTS.md`](../fusion/RESULTS.md)）。合格基準 P1〜P6 を一つも満たさず、v1.0 は「優位性なし」と記録しています。
  未接触の7銘柄・約15年分で1,609回、平均 +0.055R/回（95%区間 −0.049〜+0.163R、t=1.07）で、ゼロとも、トレンド方向にでたらめに入る素朴なやり方（同じ出口）とも区別できませんでした。
- 既知の事実: 設計時の開発期間（2013〜2017）の成績は、約190構成の探索による**選択バイアスを含みます**。
  前身 MinCore の審査ホールドアウトは、2010〜2012 が PF1.06、AUDUSD・USDCAD 2013〜2017 が PF0.76 でした。
  従来版EA・4P-Score（`README_SIGNAL.md`）も、実データではマイナスでした。
- したがって SPEC §21 の「判定後の扱い」のとおり、この EA は**自動売買を無効（既定 OFF）のまま**、シナリオ表示・パネル・通知の**裁量の補助ツール**としてだけ使ってください。
  改良は v1.1 として事前登録し直し、新しい未接触データで1回だけ評価します。
- パネルの固定文言のとおり、仕様上の性格は「勝率 25〜30% 前後、損益の中央値は −1R、利益は週末まで持った少数の取引に集中、10〜20 連敗は想定内」です。

## セットアップ

### 1. コピーとコンパイル

1. `FX_Fusion_EA.mq5` を `MQL5\Experts\` にコピーします（MT5 → ファイル → データフォルダを開く → MQL5 → Experts）。
2. MetaEditor で開いて「コンパイル」します。`#include <Trade\Trade.mqh>` だけを使い、DLL は使いません。MT5 build 4000 以降を想定しています。
   ソースは UTF-8（BOM 付き）です。BOM のないファイルを ANSI として読む MetaEditor でも日本語が化けないようにしています（保存し直すときも UTF-8 のままにしてください）。
3. 注意: 開発環境に MetaEditor がなかったため、**EA ファイル自体のコンパイルはまだ確認していません**。
   判定エンジン部は C++ に写して動作まで確認しました。MT5 接続部（CopyRates・CTrade・チャートのオブジェクト・ファイル・通知・GlobalVariable）は、
   MQL5 の API を代用の宣言に置き換えて g++ で構文と型だけを確かめました（`mt5/engine_check/conncheck.py`。API の引数の形は代用の宣言どおりかしか分からない）。
   自動売買の主な経路は、API の模擬で動かすシナリオ試験（`mt5/engine_check/conntest.cpp`）で確かめましたが、MT5 の本当の振る舞いの確認ではありません。
   初回のコンパイルで警告やエラーが出たら、まず `//@@ENGINE_END` より後の接続部を見てください。

### 2. 履歴の準備（H1 10,000本）

- 日足レベルのスイング帳簿が過去 8,000 本（＋深さ72）を使うため、評価開始前に **H1 の確定足を 10,000 本以上**用意します（約1年半分）。
- ツール → オプション → チャート → 「チャートの最大バー数」を **10000 以上**にし、監視する銘柄の H1 チャートを開いて履歴をダウンロードします（チャートを過去へスクロール、または `Home` キー）。
- EA は起動時に `InpHistoryBars`（既定 10000）本を読み込みます。
  - 足りない間は、手元より古い足を要求して端末にサーバーから読み込ませながら、**最大5分**（時刻で数える。初回の読込はタイマーからだけ行い、1回に1銘柄ずつ）待ちます。
    サーバーの最初の足に届いた・「チャートの最大バー数」に届いたときは、待たずにある分で始めます。600 本未満では始めません。待っている間のログは5分に1回です。
  - 8,100 本未満で始めると、エキスパートログとパネルに「履歴○本（推奨10000本）」と出ます。この状態では D1 帳簿と節目が全履歴の Python と異なりうるので、
    履歴をそろえてください。履歴が 500 本以上増えていれば、EA は次の休場明け（週明けの最初の足）に自動で読み直します（すぐそろえたいなら再起動）。

### 3. チャートに付ける

1. 監視したい銘柄の **H1 チャート**を開きます（判定は常に H1 の確定足なので他の時間足でも動きますが、SMA・スイング・注文線を H1 の足に重ねて描くため H1 を推奨します）。
2. ナビゲーターから `FX_Fusion_EA` をドラッグ＆ドロップし、パラメータを設定して OK。
3. 「アルゴリズム取引を許可」は、`InpAutoTrade=true` のときだけ必要です（通知とパネルだけなら不要）。
4. 新しい H1 足の検出は `OnTimer`（既定 5 秒ごと）で全銘柄を巡回して行うので、**1つのチャートに付けるだけ**で `InpSymbols` の全銘柄を監視できます。
5. 同じ口座・同じマジックナンバーの同じ銘柄は、**1つのチャートの EA だけが監視**します（端末のグローバル変数 `FUSL_<magic>_<銘柄>` で監視の権利を取ります）。
   2つ目のチャートに付けると、その銘柄は「別のチャートの EA が監視中」として監視せず、全銘柄が重なるときは起動に失敗します（通知や発注の二重化を防ぐため）。
   - 1つ目の EA を外すと、2つ目が1分以内に引き継ぎます。
   - 1つ目が異常終了などで止まったとき（権利が残ったまま生存記録が止まる）は、1分ごとの確認で生存記録が2回続けて変わらないことを（自分の時計で）確かめてから引き継ぎます（止まってから2〜3分）。
     生存記録が無いだけでは引き継ぎません（同時に起動した・PC のスリープから戻った直後に、まだ動いている持ち主から権利を奪わないため）。
   - 監視中の EA は10秒ごとに権利をまだ持っているかを確かめ、別のチャートに移っていたら、その銘柄の監視・注文・決済をやめて知らせます。

### 4. 監視銘柄

- `InpSymbols` にカンマ区切りで指定します（例: `EURUSD,GBPUSD,EURJPY,XAUUSD`）。空ならチャートの銘柄だけです。
  **自動売買（`InpAutoTrade=true`）では空にできません**（チャートの銘柄を切り替えたときに、元の銘柄の注文・建玉が管理から外れるため。テスターを除く）。
- `EURUSD.a`、`XAUUSDm` のような接尾辞つきでよく、気配値表示に自動で追加されます。
- 名目スプレッド s_nom（SL バッファの下限と仮想ブローカーの約定に使う固定値。SPEC §10.3）は、次の順に決めた「表の名前」で表から引きます。
  1. `InpSymbolMap`（例 `m.EURUSD=EURUSD;GOLD#=XAUUSD`）に書いてあればその名前
  2. 銘柄名の**先頭6文字**（大文字。`GOLD` で始まる銘柄は `XAUUSD`）が表にあればそれ
  3. 英数字だけにした銘柄名が表の名前（と `GOLD`）をただ1つ含めばそれ（`m.EURUSD`・`#XAUUSD` のような接頭辞つき）
  4. それ以外は表にない銘柄（起動時にエキスパートログに注意が出ます）

  2〜4 は照合ハーネス（`fusion/mt5_parity.py` の `symbol_base`）と同じです。`InpSymbolMap` を使ったときは、ハーネスの `--symbol` に表の名前を渡してください。

| 銘柄 | s_nom | 銘柄 | s_nom |
|---|---|---|---|
| EURUSD | 0.00010 | GBPJPY | 0.025 |
| GBPUSD | 0.00015 | AUDUSD | 0.00012 |
| USDJPY | 0.010 | USDCAD | 0.00015 |
| EURJPY | 0.015 | AUDJPY | 0.015 |
| XAUUSD（GOLD〜） | 0.30 | 表にない銘柄 | `InpSpreadPointsDefault` ポイント（既定 20） |

- 表にない銘柄は Python 側（`fusion/broker.py` の `NOMINAL_SPREAD`）に s_nom がないため、照合には `_info.csv` の s_nom を Python に渡す必要があります。
- 初心者は 1〜3 銘柄に絞ることを勧めます（SPEC §11.5）。描画はチャートの銘柄だけに行い、通知とパネルは全銘柄に出ます。

### 5. スマホへのプッシュ通知

- PC 側: ツール → オプション → 通知タブ → 「プッシュ通知を有効にする」にチェックし、MetaQuotes ID を入力。
- スマホ側: MT5 アプリ → 設定 → チャットとメッセージ → MetaQuotes ID を確認。
- `InpPushNotify=true`（既定）で送ります。`InpAlertPopup=true` にすると PC のアラート画面にも出ます。
- 送信は 6.5 秒ずつあけて順に行います（`SendNotification` の送信回数の上限に備えるため）。1件は 255 文字で切ります。
  約定・決済・休場明け・要対応（決済の失敗など）は、ほかの通知より先に送ります。15分以上送れなかった通常の通知（ARMED・INVALID など）は捨てます（エキスパートログには残ります）。
  送信回数の上限に当たったとき（エラー 4518）は、捨てずに次の機会に送ります。
- 端末のプッシュ通知が無効だと、起動時にエキスパートログに注意が出て、通知はエキスパートログと `FusionEA/notify_log.csv` にだけ残ります。
- 送った通知は、送信の成否にかかわらず `FusionEA/notify_log.csv`（UTF-8、追記だけ）に時刻つきで残します。デモのフォワードの記録にも使えます。

### 6. サーバー時間のオフセット

- 時刻ルール（金曜20時の新規停止、22時の全決済など）は「サーバー時間＝ニューヨーク時間＋7時間」（NY クローズ 17:00＝00:00。GMT+2/+3 で米夏時間に連動）を前提にしています。
  多くの MT5 ブローカーはこの時刻で、`InpServerOffsetHours=0` のままでよいです。
- 確かめ方: H1 チャートで**週明け最初の足が月曜 00:00、金曜の最後の足が 23:00** なら 0 です。
  週明けの最初の足が日曜 22:00 なら −2、日曜 21:00 なら −3 を入れます（`InpServerOffsetHours` ＝ ブローカーのサーバー時間 −（NY+7）［時間］）。
- 固定の時差だけなので、ブローカーの夏時間切替が NY とずれる週は時刻ルールが1時間ずれうることに注意してください。
  EA は1日1回、サーバーの GMT オフセット（`TimeTradeServer − TimeGMT`）と米国の夏時間から期待値を計算し、`InpServerOffsetHours` と違えばパネルに赤字で出して通知します
  （判定は変えません。`TimeGMT` は PC の時計とタイムゾーンから計算するので、PC の設定が狂っていると誤って出ることがあります）。
  点検するのは、取引サーバーにつながっていて新しい気配が届いているとき（最後の気配の時刻が10分以内）だけで、つながり直すたびに点検し直します
  （接続の前や週末は `TimeTradeServer` が古い時差で計算されていることがあるため）。
- 換算後の時刻で土日に入った足は捨てます（オフセット 0 なら `fusion/data.py` の `drop_weekend` と同じ）。
- ブローカー固有の休場日・早仕舞い日は `InpExtraClosedDays` / `InpExtraEarlyDays` に `YYYY.MM.DD;YYYY.MM.DD` の形で追加します。照合するときは Python 側に同じリストを渡します。

### 7. 起動時に起きること

1. 銘柄ごとに H1 の確定足を読み込み、Python の `run_h1` と同じループを**先頭から仮想で再生**して、約定済み集合・待機注文・建玉を復元します（この間は通知しません。ログには `phase=REPLAY` で書きます）。
   読込と再生は `OnInit` の中では行わず、最初のタイマー（テスターでは最初のティック）から1回に1銘柄ずつ行います。
2. 再生の結果（いま待機注文があるか）は「通知済み」として扱うので、再起動のたびに同じ ARMED が届くことはありません。
   読み直し（下の 3.）で待機注文が新しく現れたとき・なくなったとき、仮想建玉が読み直しの前と変わったとき（有無・方向・約定時刻・約定価格・SL）は知らせます。
3. 以後は新しい確定足を末尾に追記し、毎時、直近の確定足を `CopyRates` で取り直して手元の足と照合します。欠け・挿入・四本値の変化があれば、読み込み直して先頭から再生します（エキスパートログに「読み込み直して再生します」と出ます。同じ日に4回目になると通知します）。
   取引サーバーにつながっていないときは進めず、足の同期（`SERIES_SYNCHRONIZED`）も最大30秒待ちます。処理が2本以上遅れたらパネルに赤字で出して通知します
   （未接続による遅れは全銘柄に共通なので、通知は1通にまとめます）。
   端末が止まっていた等で何本かまとめて追記したときは、最後の足より前のイベントは個別に通知せず「追いつき処理 ○本」の1通にまとめます（ログには全部書きます）。
4. エキスパートログに「○本を読み込み、○〜○を再生（仮想取引 ○回、総R ○）。待機注文 あり/なし、建玉 あり/なし」と出れば準備完了です。
5. 「パラメータの変更」「時間足の変更」での再初期化でも、同じ手順で読み込み直します（そのとき前の回のログは `FusionEA/old/` に移します）。
6. 取引サーバーにつながって10秒たったら1回、**この EA が管理していない FUSION の注文・建玉**（コメントが `FC` で始まるもの）を数え、あれば知らせます。
   監視銘柄・マジックナンバーを変えた、自動売買を OFF にした、などで、トレール・週末決済・休場明けの決済から外れたものです（別のチャートの FX_Fusion_EA が監視している銘柄のものは数えません）。
   パラメータの変更で再初期化したときも、つながっていれば10秒後に数えます。

## 判定の流れ

### 足ごとの処理順（`fusion/strategy.py` の `run_h1` と同じ）

```
新しい H1 足が始まった時点
  1) 休場明けフォールバック: 前の足の確定から 12 時間以上空いていれば、待機注文を取消し、
     建玉はその足の始値で全決済（GAP_FALLBACK）

足 t が確定した時点（開始時刻＋1時間）
  2) 逆指値の約定判定（買い: Ask 高値 ≥ price、売り: Bid 安値 ≤ price。窓開けは始値で約定）
  3) 建玉の足処理（寄り付きが SL を越えていれば SL_gap、足の中では SL を優先。約定した足は SL だけ判定）
  4) 確定時の管理: 決済足なら終値で全決済（WEEKEND）、そうでなければ 4H 構造トレール
  5) 時刻・建玉による見送り（T1 休場日 / T2 新規停止 / T3 ロールオーバー / T4 建玉あり / T5 決済足）
     → 待機注文があれば取消（T4 を除く）
  6) 新規判定: 買い → 売りの順に下のゲートを評価し、両方成立したらスコアの高い方（同点は買い）
     候補なし ……………… 待機注文を取消（INVALID）
     新しい key ……………… 逆指値を置く（ARMED）
     同じ key ………………… 価格・SL を今回の値に置き直す（UPDATE）
```

key＝(方向, 戻り高値 SH の足)。**1セットアップにつき約定は1回**で、同じ key は約定後 R06 になります。待機注文に期限はなく、
取消は構造・時刻・建玉の条件だけで決まります。1銘柄につき建玉1・待機注文1までです。

### ゲート（評価順＝理由コード順。SPEC §8）

| コード | 条件（買い。売りは鏡像） | 既定 | 入力 |
|---|---|---|---|
| R00 | 指標の準備未了（ATR14・SMA80・SMA80[t−12]） | ON | — |
| R01 | G1 不成立: BIG 帳簿の直近2高値が切上げ、かつ直近2安値が切上げ、かつ終値 > 直近安値、ではない | ON | — |
| R02 | G2 不成立: 押しの起点以降の安値と SMA80 の距離の最小値が 0.5ATR を超える（4H MA に届いていない） | ON | `InpZONE_ATR` |
| R03 | 押しの内側に 1H 戻り高値がない、または直前安値 L0 がない | ON | — |
| R04 | 安値切上げの崩れ（戻り高値以降の最安値 ≤ L0） | ON | — |
| R05 | 消化済み（戻り高値の後に終値で戻り高値を越えた） | ON | — |
| R06 | 約定済みのセットアップ（同じ key） | ON | — |
| R07 | G3 遅すぎ（ブレイク水準が SMA80 から 3ATR 超） | OFF | `InpG3` |
| R08 | MA 傾き（slope80·d < 0。4H MA が逆向き） | ON | `InpSLOPE_MIN` |
| R09 | R 過小（R < 0.8ATR） | ON | `InpR_MIN_ATR` |
| R10 | R 過大（R > 3.0ATR。d1_gate=soft で日足逆行なら 1.5ATR） | ON | `InpR_MAX_ATR` |
| R11 | 日足逆行（T_D1×d = −1） | OFF | `InpD1Gate=strict` |
| R12 | 乖離（gap > 8 かつ拡大中） | OFF | `InpGapGate` |
| R14 | 背後の支えなし（n_sup=0） | OFF | `InpSupportGate` |
| R15 | 反対勢力が近い（rr_cf < 2.0） | OFF | `InpClearGate` |

R13（1H 転換型）と R16（目標が近い）は `oku_only`・`kenjin_only` 構成専用で、この EA の入力にはありません。
ゲートをすべて通ると、注文価格・SL・R が決まります。

```
price = 戻り高値 SH + 0.05×ATR            （逆指値。売りは戻り安値 − 0.05×ATR）
buf   = max(0.2×ATR, 3×s_nom)             （スプレッド下限つきバッファ）
SL    = 戻り高値以降の最安値 runLow − buf  （切上げ安値の外）
R     = price − SL                         （0.8ATR ≤ R ≤ 3.0ATR でなければ R09／R10）
```

### 時刻ルール（SPEC §2.6。時刻は換算後のサーバー時間、「○時以降」は足の確定時刻）

| 区分 | 条件 | 新規・待機注文 | 建玉 |
|---|---|---|---|
| 休場日 | 12/25、1/1（XAUUSD は Good Friday も）、`InpExtraClosedDays` | 一切置かない（T1） | その日の最初の足の確定で全決済 |
| 早仕舞い日 | 12/24、12/31（XAUUSD は感謝祭翌日・独立記念日も）、`InpExtraEarlyDays` | 17時以降は取消・新規なし（T2） | 19時以降の足の終値で全決済（WEEKEND） |
| 週末前・休場前日 | 金曜、または翌平日が休場日 | 20時以降は取消・新規なし（T2） | 22時以降の足の終値で全決済（WEEKEND） |
| ロールオーバー | 23時以降〜1時より前 | 取消・新規なし（T3。毎日なので通知しない） | 保有を続ける |
| 休場明け | 前の足の確定から次の足の始まりまで12時間以上 | 取消 | その足の始値で全決済（GAP_FALLBACK） |

### 出口

| 決済理由 | 内容 |
|---|---|
| SL | 初期 SL に到達（到達まで動かさない） |
| TRAIL | 4H 構造トレールで引き上げた SL に到達。毎回の確定時に、最新の BIG 安値（約定足 − 12 本より後に確定したもの）− max(0.2ATR, 3×s_nom) が現在の SL より上で、終値もその上にあるときだけ SL を引き上げる（次の足から有効） |
| SL_gap | 寄り付きが SL を越えていた（始値で決済） |
| WEEKEND | 週末・休場前・早仕舞いの決済足の終値で全決済 |
| GAP_FALLBACK | 休場明け（12時間以上の空き）の足の始値で全決済 |
| END | EA を止めたとき（OnDeinit）に、最後の確定足の終値で残りの仮想建玉を閉じたログ上の行。照合用で、実際の決済ではない |

利確（TP）はありません。パネルと通知の TP1／TP2 は「目安」の表示だけです。

### スコアとグレード（情報用。既定では足切りに使わない。SPEC §9）

| 項目 | 配点 | 判定 |
|---|---|---|
| S1 4H MA の向き | 20／10／0 | slope80·d ≥0.10／≥0／<0 |
| S2 押しの深さ | 15／8 | depth≤0（SMA80 に到達・貫通）／≤0.5ATR |
| S3 背後の支え | 15／8／0 | n_sup≥2／1／0（HZ＝touch≥2 の節目、FLIP＝レジサポ転換、KEY＝押しの起点より前の BIG 安値） |
| S4 日足との関係 | 20／10／0 | 合致／中立（不明を含む）／逆行 |
| S5 前方の余白 | 15／10／5／0 | rr_cf ≥3（反対勢力なしを含む）／≥2／≥1／<1 |
| S6 MA の状態 | 8＋7 | 乖離が悪化していなければ +8、押しの中で SMA20 と SMA80 が 0.5ATR 以内に収束していれば +7 |

グレード: S ≥80、A 65〜79、B 50〜64、C <50。スコアで絞ると取引が6割減って 4P-Score の失敗を繰り返すため、既定では全件を出します。

## 通知の例

先頭のタグは、通知のみのとき `[FUSION]`、自動売買のとき `[FUSION自動]` です。価格は銘柄の桁数、R は pips
（3桁・5桁の銘柄では point×10、それ以外は point。GOLD は 0.01）で表します。数値は例です。

| 種類 | いつ | 例 |
|---|---|---|
| ARMED | 新しい key で待機注文を置いた | `[FUSION] EURUSD 買い ① S(83) 逆指値1.08520 SL1.08180 R=34.0pips TP1目安1.08905(1.1R) 支え:HZ 日足:合致 反対勢力:1.6R` |
| 修正 | 同じ key の置き直しで、価格か SL が 0.2ATR を超えて動いた | `[FUSION] EURUSD 買い ① 修正 S(83) 逆指値1.08560 SL1.08200 R=33.6pips …` |

| 遅延 | 確定足の処理が2本以上遅れている（足の取り直しの失敗・同期待ちは銘柄ごと、未接続は全銘柄で1通） | `[FUSION] EURUSD 注意: 確定足の処理が 2 本遅れている（足の取り直しに失敗）` |

通知の重複を防ぐ規則:

- 同じ key の ARMED（置き直し）は、価格か SL の変化が **0.2ATR を超えたときだけ**通知します。毎日のロールオーバー明けの置き直しは通知しません。新規停止の後に置き直したときは通知します。
- 起動時の再生中は通知しません。再生の結果の待機注文は「通知済み」として扱います。
- 自動売買中は、ZONE を除いて**実注文の側だけ**が通知します（仮想側はログのために並行して動きます）。
- 自動売買の INVALID は、注文を実際に取消できてから通知します（取消の前に約定していたら、INVALID ではなく約定を通知します）。
- 自動売買の成行は、約定を確かめてから「約定（成行）」として通知します（受け付けただけでは通知しない）。
- 見送り（越え幅・最小ロット・証拠金・成行が約定しない）は、同じセットアップ・同じ理由なら2回目からログだけにします。
- 端末・EA・口座の理由で取引できないこと、未接続による遅れは、全銘柄で1通にまとめます。
- ストラテジーテスターでは SendNotification と Alert は使わず、エキスパートログに出すだけです。

通知の読み方（ARMED の例）: 「① S(83)」はパターン①とグレード（スコア）、「逆指値／SL／R」が注文の中身、「TP1目安」は最寄りの目標の節目（表示だけで利確はしない）、
「支え」は押しの背後の節目の種類（HZ／FLIP／KEY、なければ「なし」）、「日足」は日足レベルのダウ状態との関係（合致／中立／逆行）、
「反対勢力」は前方の強い節目か SMA480 までの距離（R 単位。なければ「なし」）です。既定では日足・支え・反対勢力は売買を止めず、判断材料として表示しています。

## パネルの読み方

チャート左上（`InpPanelX`・`InpPanelY`。ワンクリック取引パネルを表示中はその下）に、銘柄ごとに5行と固定文言を表示します
（60文字で折り返し、続きの行は4文字下げます。背景の幅は一番長い行に合わせ、チャートの高さに収まらない行は「…ほか N 行」にまとめます。テスターの非ビジュアルモードでは表示しません）。
未接続・時差の食い違い・処理の遅れ・自動売買できない状態（全銘柄に共通の理由は見出しの下に1行、銘柄ごとの理由はその銘柄の下）・決済の再試行中は、赤字の行で出します。
市場が閉まっていて決済を待っているときは、橙の行（「市場が閉まっているため、取引が再開したら決済する」）で出します。

```
FUSION-CORE v1.0（H1 単一時間足） シグナル通知のみ fusion（既定）
EURUSD ARMED G1:UP 日/4H/1H:+1/+1/-1 END0
  depth-0.12 slope80+0.35 conv0.41 gap+3.2 R/ATR1.45
    S(83)=20/15/8/20/5/15
  直近 買:OK 売:R01 エリア:買い方優勢 上1.09120(4) 下1.08350(3)
  待機:買い逆指値 1.08520 SL1.08180 TP1目安1.08905 TP2 1.09300
  確定足2026.03.11 13:00 仮想累計 23回 勝率30% 総R+4.5 連敗2(最大7) 次の全決済
    2026.03.13 22:00
勝率は25〜30%前後、損益の中央値は−1R、利益は週末まで持った少数の取引に集中、
10〜20連敗は想定内。優位性は未確認（最終検証は不合格）。
裁量で分割・建値・早利確を加えると別の戦略になる
```

| 行 | 内容 |
|---|---|
| 見出し | 版・動作モード（シグナル通知のみ／自動売買ON）・構成名（既定なら `fusion（既定）`、変えていれば `F+G3+d1` のような差分） |
| 1行目 | 銘柄、**状態**、G1 の向きと理由、持続型ダウ状態 日/4H/1H（+1 上昇／0 中立／−1 下降）、END（4H の終了の兆し。1 なら高値切下げ or 安値切上げが出た）、戦争状態（日足と 4H が逆向きで END=0）、準備中の注記 |
| 2行目 | G1 方向（なければ買い側）の評価値: depth（押しと SMA80 の距離の最小。×ATR。≤0.5 で G2 成立）、slope80（4H MA の傾き。≥0 で通過）、conv（SMA20 と SMA80 の収束）、gap（4H MA と日足 MA の乖離）、R/ATR、グレード(スコア)=S1/S2/S3/S4/S5/S6 |
| 3行目 | 直近の足での買い側・売り側の理由コード（最初の不成立。全条件を満たした候補は `OK`）、時刻・建玉による見送り、**エリア判定**（現在値 ±2ATR で touch 最大の節目を基準に買い方優勢／売り方優勢／中立）と直上・直下の節目（括弧は強度 touch） |
| 4行目 | 待機注文（逆指値・SL・TP1/TP2 の目安）か建玉（約定価格・現在の SL・R・含み R・MFE）。自動売買では実注文を先に、区切りの後に仮想側の状態（仮想:建玉／待機／なし）を示す |
| 5行目 | 最後に処理した確定足の開始時刻、仮想取引の累計（回数・勝率・総R・現在の連敗・最大連敗）、自動売買では実取引の回数と総R（起動後の分）、次の全決済の予定時刻（週末・休場前の決済足の確定時刻） |
| 固定文言 | SPEC §16.3 の文言。仕様上の性格を忘れないための注意書き |

### 状態（1行目）

| 状態 | 色 | 意味 |
|---|---|---|
| IDLE | 灰 | G1 不成立（4H レベルの構造がない） |
| WATCH | 薄黄 | G1 成立だが ZONE ではない。G2 未達（押しが 4H MA に届いていない）、MA が逆向き（R08）、約定済み（R06）、任意ゲートで見送りなど |
| ZONE | 黄 | G1・G2・MA 傾きは OK でトリガー待ち（R03〜R05）、または R の範囲外（R09／R10） |
| ARMED | 緑 | 逆指値を置いている |
| FILLED | 水色 | 建玉あり |
| PAUSED | 橙 | 時刻ルールで停止中（休場日・新規停止・ロールオーバー・決済足） |

G1 の表示: `G1:UP`／`G1:DOWN`／`G1:NEUTRAL(スイング不足)`／`G1:NEUTRAL(上昇終了:終値≤押し安値)`／`G1:NEUTRAL(下降終了:終値≥戻り高値)`／`G1:NEUTRAL(高安が混在)`。
「上昇終了」は、高値・安値とも切上げだが終値が押し安値以下に沈んだ状態で、「終了≠転換」の表れです。反対側の安値切下げ＋高値切下げが確定して初めて DOWN になります。

### 累計の注意

パネルの累計は、**読み込んだ期間（既定 10,000 本＝約1.6年）の仮想取引**だけです。起動後の稼働分は足されますが、それより前の通算は持ちません。
EA を再起動すると、その時点の履歴から再生し直します。

### チャート描画（チャートの銘柄だけ。`InpDrawChart=true`）

| 描くもの | 見え方 |
|---|---|
| SMA20／SMA80／SMA480 | 青（細）／赤／黄。直近 240 本 |
| BIG スイング（4H レベル） | 高値に赤の下向き矢印、安値に水色の上向き矢印。直近 1,200 本 |
| 節目（水平線） | 現在値 ±6ATR のうち touch 上位 8 本。**太さ＝強度**（touch 1 は点線）。現在値より上は赤系、下は青系。ツールチップに `節目 touch=4 高2安1 日足級` |
| 待機注文 | 逆指値（緑の破線）、SL（赤の破線）、TP1／TP2 の目安（黄の点線。表示だけ） |
| 仮想建玉 | 約定価格（白）、SL（赤の実線。構造トレールで動く） |

オブジェクトの名前は `FUSION_` で始まり、EA を外すと自分のオブジェクトだけを消します。描画はすべて背景（ローソク足の後ろ）に置くので、パネルの上には重なりません。

## ログ（CSV）

`InpWriteLogs=true`（既定）で、`MQL5/Files/FusionEA/`（`InpLogsCommon=true` なら `Terminal/Common/Files/FusionEA/`）に銘柄ごとに書きます。
ストラテジーテスターでは、`InpLogsCommon=false` のままだと各エージェントの砂場（`Tester/Agent-*/MQL5/Files/FusionEA/`）に出て、エージェントの掃除で消えることもあります。
照合用に取り出すなら `InpLogsCommon=true` にしてください。最適化中はログを書きません。

- `_eval`・`_trades`・`_bars`・`_info` は、起動・読み直しのたびに作り直します（再生分を含む）。作り直す前の4つは
  `FusionEA/old/<銘柄>_<日時>/` に移し、銘柄ごとに `InpLogKeep`（既定 10）世代まで残します。
  時間足やパラメータを何度か変えると世代はすぐ入れ替わるので、稼働中の評価行・仮想取引（`phase=LIVE`）は `_live.csv`・`_live_trades.csv` にも追記します（消えない）。
- `_real.csv`・`_live.csv`・`_live_trades.csv`・`notify_log.csv` は追記だけで、起動・読み直しでも消しません。
- ストラテジーテスターの実取引は `_real_tester.csv` に書き、テストごとに作り直します（ライブの `_real.csv` に模擬の取引が混ざらないように）。テスターでは `_live*.csv` と `notify_log.csv` は書きません。
- 時刻はサーバー時間 `YYYY.MM.DD HH:MM`、価格は小数10桁、カンマ区切り、ヘッダー行つきです。`_info.csv` は ASCII だけで書きます。列の定義の全文は EA ファイル冒頭のコメントにあります。

| ファイル | 内容 |
|---|---|
| `<銘柄>_eval.csv` | 足ごと・方向ごとの評価。`code` は R00〜R16（最初の不成立）、`ARMED`（新しい key で待機注文。Python の `funnel['ARMED']` と同数）、`UPDATE`（同じ key の置き直し）、`LOSE`（全条件を満たしたがスコアで負けた）、`T1〜T5`（時刻・建玉による見送り。`run_h1` と同じく 決済足 T1/T5 → 新規停止 T2 → ロールオーバー T3 → 建玉あり T4 の順に付ける）。`phase` は `REPLAY`（起動時の再生）／`LIVE` |
| `<銘柄>_trades.csv` | 仮想ブローカーの取引（約定・決済の時刻と価格、理由、R、保有本数、key、スコア、MFE/MAE）。`fusion/broker.py` と同じ計算。停止時に `END` 行を書く |
| `<銘柄>_bars.csv` | 判定に使った H1 確定足（Time,Open,High,Low,Close。時刻はサーバー時間のまま、換算後の土日を除いた後）。`fusion.data.load_mt5_csv` で読める。照合では**この足を先頭から Python に渡す**（`InpServerOffsetHours` が 0 でなければ、ハーネスが `_info.csv` の `server_offset_h` で時刻を NY+7 に戻して回す） |
| `<銘柄>_info.csv` | 照合に必要な設定（ASCII）: ea（版）、symbol、base（表の名前）、s_nom、is_xau、server_offset_h、first_bar_time（最初に読み込んだ足）、first_eval_time（判定開始＝読込の93本目）、bars_loaded、history_bars_input（`InpHistoryBars`）、config（`fusion`／`F+G3+d1` の形）、core_changed（核心パラメータを変えたら 1）、switches、params、extra_closed/early、login、magic、auto_trade、tester |
| `<銘柄>_real.csv` | 自動売買の実際の取引（`InpAutoTrade=true` のとき。追記だけ。同じ建玉は1行だけ。最適化中は書かない。テスターでは `<銘柄>_real_tester.csv`）。列は entry_time（約定の時刻）、dir、entry、initial_sl、exit_time、exit_reason、R、key_time、score、ticket、exit_price、volume、planned_entry（計画した逆指値）、slippage_pts、profit、swap、commission、login、magic。決済理由は、EA が決済したときは要求した理由（WEEKEND／GAP_FALLBACK／TRAIL）、それ以外は約定の理由（SL／TRAIL／STOPOUT／TP／MANUAL／EXPERT／OTHER）。決済の約定を履歴で確かめられなかったときは UNKNOWN |
| `<銘柄>_live.csv` | `_eval.csv` と同じ列の、稼働中（`phase=LIVE`）の行だけ。追記だけ（起動・読み直しでも消さない）。テスター・最適化では書かない |
| `<銘柄>_live_trades.csv` | `_trades.csv` と同じ列の、稼働中に決済した仮想取引だけ（`END` 行は書かない）。追記だけ。テスター・最適化では書かない |
| `notify_log.csv` | 送った通知（UTF-8。server_time、local_time、login、magic、message）。追記だけ。テスターでは書かない |

ファイル名の銘柄部分は、英数字・`.`・`_`・`-` 以外を `_` に置き換えます（例: `EURUSD.a_eval.csv`）。

## 運用の段階（SPEC §16.6）

```
【段階1】通知のみでチャートを確認  ← v1.0 はここまで
  InpAutoTrade=false（既定）。届いた ARMED／FILLED／EXIT をチャートで確かめ、

【段階2】デモ口座で自動売買（InpAutoTrade=true、InpRiskPercent=0.5）
  SPEC §21 の最終検証（未接触データで1回）に合格し、デモでのフォワード3か月（通知のみ、30シグナル以上、
  Python との一致を確認）を終えた後に限る。_real.csv と _trades.csv の差（実約定とのずれ）を記録する。
```

1. **検証の合格**: SPEC §21 の最終 OOS（未接触データで1回だけ）で P1〜P6 をすべて満たし、結果が `fusion/RESULTS.md` に載っていること（v1.0 は不合格）。
2. **MT5 での照合**: ストラテジーテスターの取引一覧（`_trades.csv`）が Python と SPEC §18 の基準で一致していること（下の照合手順）。
3. **デモのフォワード 3か月**: 通知のみで 30 シグナル以上を観察し、Python との一致を確認していること。
4. **口座の条件**: ヘッジング口座か、ネッティング口座で同じ銘柄を他の EA や手動の取引と共有しないこと。ブローカーが注文コメントを書き換えないこと（後述）。GTC の待機注文が置けること（置けないブローカーでは DAY で置き、失効したら置き直す）。
5. **稼働環境**: 24時間動く端末（VPS など）。巡回は `OnTimer` なので、端末が止まっている間は約定判定・トレール・週末決済も止まります。

### 自動売買の動き（SPEC §16.5・§17.5）

- 判定は仮想側と同じ `EvalBest` に、**実際に約定した key の集合**を渡して行います。仮想ブローカーも並行して動き、ログと照合は仮想側を書きます。
- 確定足ごとに「置きたい注文」（なし／key・価格・SL）を決め、実際の注文をそれに合わせます。置けない・直せない・取消せないとき（STOPS_LEVEL・FREEZE_LEVEL・
  拒否・再クオートなど）は、**同じ足の中で再試行**します（エキスパートログは5分に1回）。待機注文の FOK/IOC を受け付けないブローカーでは RETURN で出し直します。
  - 再試行の間隔は、価格の変化・再クオート・接続・STOPS_LEVEL の待ちなどは **10 秒**、証拠金不足・取引停止・要求が多すぎる・注文数の上限などの拒否は **1分、その後は5分**です（サーバーに同じ要求を送り続けない）。
  - 市場が閉まっている（`MARKET_CLOSED`）と返されたら、その銘柄の注文・決済・トレールは**新しいティックが来るまで**（来なければ30分ごとに1回確かめる）送りません。
  - ストラテジーテスターでは、待ち・再試行の間隔を模擬時刻（`TimeCurrent`）で数えます（実時間の `GetTickCount` だと、速いテストで再試行がほとんど起きないため）。
- 発注: BUY STOP／SELL STOP（SL つき、TP なし）。発注時に Ask（Bid）がすでに逆指値を越えていれば成行で入ります（Python の「始値約定」に当たります）。
  ロットは実際に入る価格からの損切り幅で計算します。足の始まりから2分を過ぎてからの成行（再起動・再接続・置けなかった注文の再試行）は、
  越え幅が max(`InpDeviationPoints`, 0.1ATR) を超えていれば見送って通知します。証拠金が足りないとき・最小ロットでリスクが目標の 1.5 倍を超えるときも見送ります
  （同じセットアップ・同じ理由の見送りは、2回目からログだけ）。
  成行は約定を確かめてから「約定（成行）」として通知します。受け付けた後に拒否される（約定しない）ときは、1つの足で**2回まで**出し直し、それでも約定しなければその足は見送ります。
- 毎時: 同じ key なら OrderModify で価格・SL を置き直し、key が変われば取消して置き直し、候補がなければ取消（INVALID。取消できてから通知）。
  STOPS_LEVEL が 0 のブローカーは「変動（スプレッド程度）」の意味のことがあるので、現在のスプレッドを最小の距離に使います。
- **二重の建玉を防ぐ**: 追っていた注文が消えたら、履歴（`HistoryOrderSelect`）で約定か取消か失効かを確かめ、結果が分かるまで次の注文を出しません。
  取消しようとした注文が約定（一部約定を含む）していたら、新しい注文は出しません。この銘柄に自分の建玉か、追っていない自分の待機注文があれば発注せず、先に取消します。
  発注の直前にも、自分の建玉・待機注文がないこと、約定済みの key（R06）でないことを確かめ直します。
  建玉を見つけたら、残っている自分の待機注文（部分約定の残りを含む）はすべて取消します。
- 約定の検出: 約定したら約定済み集合に入れ、**その足では新しく置きません**（Python も約定で待機注文を使い切り、次の確定足で判定し直す）。計画価格との差（スリッページ）とあわせて通知します。
  約定してすぐ SL で閉じた場合も、約定と決済をまとめて記録・通知し、同じ足でも次の足からも同じセットアップに入り直しません（R06）。
  約定の結果を履歴で60秒たっても確かめられないときも、その足では置き直しません。同じ建玉は `_real.csv` に1回だけ記録します（記録した建玉 ID を覚える）。
- 建玉が2本以上ある（一部約定の後の注文・手動で同じマジックを使った等）: 【要対応】を1回知らせ、追っている1本だけをトレールします（開いている建玉を決済済みとして記録しない）。
  週末・休場明けの決済は全部に行い、追っていなかった建玉の決済も約定履歴から `_real.csv` に記録します。
- スプレッド防御: 足の確定時（次の足の最初のティック）のスプレッドが 3×s_nom を超えていれば、その足では武装・修正せず、待機注文を取消して（取消できたら通知）次の足で評価し直します。
- トレール: 仮想側と同じ候補を PositionModify で送ります。`new_SL < Bid − STOPS_LEVEL`（売りは逆）で、いまの SL が FREEZE_LEVEL の外のときだけで、
  置けなければ同じ足の中で再試行します。価格がすでに新しい SL を越えていたら（Python ではその足で SL に掛かる）、成行で決済します（理由 TRAIL）。
- 週末・休場・早仕舞いの決済: 決済足の終わりの **2分前**から（市場がその足の終わりで閉じる日にも決済できるように）、遅くとも次の足の最初のティックで成行決済します。
  **建玉が消えるまで再試行**し（再クオートは3回まで続けて取り直す。間隔は上の「再試行の間隔」）、最初の失敗と5分たっても決済できないときに【要対応】をプッシュします。
  市場が閉まっていた（`MARKET_CLOSED`）ときは、手動でも決済できないので【要対応】は送らず、「取引が再開したらすぐ決済します」を1回知らせて、再開後の最初のティックで決済します。
  休場明けは、形成中の足の最初のティックで成行決済し、待機注文を取消します。決済・取消は、履歴の読み直し中でも行います。
- 切断・停止の後: 起動・再接続での引き継ぎや、何本かまとめて処理した（追いつき処理）後に、建玉の約定より後で決済足が確定していた・休場明けを過ぎていた（金曜の夜に切断して月曜に再接続した等）なら、
  その場ですぐ成行で決済し、経緯を通知します（仮想側の Python はその足で WEEKEND・GAP_FALLBACK として閉じている）。
- 接続: 口座の引き継ぎと発注は、取引サーバーにつながって **10 秒たってから**行います。つながり直したら、口座の注文・建玉・約定履歴を読み直します。
- 取引の可否: 端末・EA・口座のアルゴ取引の許可と、銘柄の取引モード（取引停止・決済のみ・買いのみ・売りのみ）を毎回確かめ、できないときはパネルに赤字で出して1回だけ通知します
  （端末・EA・口座の理由は全銘柄で1通、銘柄の理由は銘柄ごと）。
- ロット: `InpRiskPercent` と損切り幅から計算し、VOLUME_STEP で切り捨て、[最小, 最大] に丸めます。
- 管理: マジックナンバーで自分の注文・建玉を見分け、**1銘柄1建玉**。注文コメントは `FC<方向>_<key の足の時刻（UNIX 秒）>`。
  初期 SL はグローバル変数 `FUS<口座>_<magic>_<銘柄>_I<建玉ID>` に置きます（建玉ごと。置いたらすぐ保存）。消すのは、その建玉が閉じたことを約定履歴で確かめたときだけで
  （口座の同期の前で建玉が見えないだけでは消さない）、履歴でも確かめられないものは30日たってから消します。
- 再起動時: 約定履歴（自分のマジック）のコメントから約定済み集合を、口座の逆指値と建玉からいまの状態を引き継ぎます（引き継いだ建玉の約定は通知しません）。
  key を読めない注文・2つ目以降の注文は取消します。つながって10秒後に1回、この EA が管理していない FUSION の注文・建玉（`FC` で始まるコメント。マジック・監視銘柄の違い、自動売買 OFF など）があれば知らせます（管理はしません）。
- 停止時: EA を外した・チャートを閉じた・口座を切り替えた・端末を閉じたときに、自分の待機注文・建玉が残っていれば、管理されなくなることをエキスパートログとプッシュで知らせます
  （パラメータ・時間足の変更とコンパイルし直しはすぐ引き継ぐので知らせません）。

### 自動売買の制約

- **ブローカーがコメントを書き換える**と、再起動のときに key を引き継げず、約定済み集合が欠けて同じセットアップに再びエントリーしうる（EA の稼働中は、発注した注文の記録で対応づけるのでコメントに頼らない）。
- ネッティング口座で同じ銘柄を他の EA・手動と共有すると、建玉の見分けが崩れる。
- 実際の約定はティックの順序と実スプレッドで決まるので、仮想側（ログ・パネルの累計）とずれる（SPEC §17.11）。スプレッド防御・STOPS_LEVEL・FREEZE_LEVEL・
  足の途中の成行の見送り・最小ロットや証拠金による見送りは実約定側だけにある。週末の決済は決済足の終わりの2分前からなので、Python の「決済足の終値」と時刻が少しずれる。
  切断・停止の間に決済足や休場明けを過ぎた建玉は、つながったときの価格で決済するので、Python（決済足の終値・休場明けの始値）と大きくずれうる。
- サーバー時間の夏時間の切替は自動では追わない（時差の食い違いは知らせるだけ）。
- 自動売買はまだデモで動かしていません（下の「検証状況」）。

### 2. 照合ハーネスで比べる


### 3. 手作業で確かめる（ハーネスを使わない場合）

```python
import pandas as pd
from fusion import data as fd, strategy as fs

bars = fd.load_mt5_csv('FusionEA/EURUSD_bars.csv')          # EA が判定に使った足（先頭から）
trades, funnel = fs.run_h1(bars, 'EURUSD')                   # 第2引数は _info.csv の base（接尾辞なし）
py = pd.DataFrame(trades)[['entry_time', 'direction', 'entry', 'initial_sl', 'exit_time', 'exit_reason', 'pnl_r', 'bars_held']]

mt['entry_time'] = pd.to_datetime(mt['entry_time'], format='%Y.%m.%d %H:%M')

print(py.head().to_string()); print(mt.head().to_string())   # 時刻・方向・約定価格・初期 SL・決済理由を並べて見る
print(sorted(funnel.items()))                                # 理由コード別の件数（_eval.csv の code の集計と比べる）
```

`InpServerOffsetHours` が 0 でないときは、Python は NY+7 の時刻を前提にしているので、`_bars.csv` の時刻をオフセットの分だけ戻して（NY+7 に換算して）Python に渡し、
結果の時刻を比べるときに戻します（`load_mt5_csv` の土日除外はサーバー時間で行うので、日曜夜の足がある時差では先に時刻を戻してから土日を除く）。
`InpExtraClosedDays`／`InpExtraEarlyDays` を使ったときは、Python 側の暦（`strategy.calendar_sets`）にも同じ日付を加えます。ハーネスはこれらを自動で行います。

### 合格基準（SPEC §18）

| 項目 | 基準 |
|---|---|
| 取引回数 | ±5% 以内 |
| エントリー | 時刻 ±1本で方向が一致する割合が 90% 以上 |
| 初期 SL | 差が 1 ポイント以内 |

差は SPEC §17 の項目（境界値・履歴・時刻・スプレッド・約定順序・欠損足）に分類して記録します。

判定エンジン部は、MetaEditor のない環境で C++ に写し、開発期間（isdata 2013〜2017）の4銘柄で Python と**完全一致**（全評価行の理由コード、候補の値、取引一覧。取引回数 136/124/142/129 は SPEC §18 の照合表どおり）を確認しています。
`fusion/strategy.py` の修正（SPEC 付録E の E-13：見送りの順序を 決済足 → 新規停止・ロールオーバー → 建玉あり に、E-14：S2 の 0 点）に合わせ直した後も、
EURUSD で全評価行（55,980 行。T2/T3/T4 を含む）と取引一覧が一致し、C++ に写したエンジンの出力を照合ハーネスに `--strict` で通して合格しています。
したがって MT5 で差が出た場合は、まず次を疑ってください。

1. **始点**: Python を `_bars.csv` の先頭以外から回していないか（持続型ダウ状態・待機注文・約定済み集合は最初の転換イベントまで始点に依存する。移動平均の最下位桁も変わる）。
2. **履歴の本数**: `InpHistoryBars` が 8,072 本未満だと D1 帳簿と節目が全履歴の Python と異なる。
3. **時差・暦**: `InpServerOffsetHours`、追加の休場日・早仕舞い日が Python 側と同じか。
4. **境界値**: runLow>L0、R の上下限、depth≤0.5 などは 1e−10 程度の差で判定が割れうる（SPEC §17.6）。
5. **自動売買の実約定**: `_real.csv` と `_trades.csv` の差は、ティック順・実スプレッド・STOPS_LEVEL・足の途中の成行の見送り・週末の決済の時刻などによるもので、判定の差ではない。
6. **値の動かない足**: ATR14 が 0 の足（14本続けて値が動かない）は、EA だけが R00 で見送る（下の「既知の差」）。実データでは起きない。

## 既知の差と制約（SPEC §17）

1. **始点と初期状態**: EA の判定は「最初に読み込んだ足から Python を回した結果」と一致します。Python を別の日から回すと、最初の転換イベントまで、持続型ダウ状態（T_D1/T_BIG/T_SMALL と、それを使う rel・S4・d1_gate）、待機注文と約定済み集合、移動平均の最下位の桁がずれうる。
2. **窓の長さ**: `InpHistoryBars` が LB+N（D1 帳簿は 8,072 本）より短いと、D1 帳簿（パターン③の G1 と節目の候補）が全履歴の Python と異なる。既定の 10,000 本なら、その後の各足で同じ範囲になる。
3. **実約定とのずれ（自動売買）**: 実際の約定はティックの順序と実スプレッドで決まる。スプレッド防御・STOPS_LEVEL・FREEZE_LEVEL による見送りと再試行、トレール時の `new_SL < Bid − stops_level`、
   足の途中の成行の見送り（越え幅が max(`InpDeviationPoints`, 0.1ATR) 超）、最小ロット・証拠金による見送り、ロットの丸め、GTC が使えないときの DAY 失効は、実約定の側にしかない。
   休場明けの決済は、Python は始値、実約定は最初のティックの成行。週末・休場前の決済は、Python は決済足の終値、実約定は決済足の終わりの2分前から（遅くとも次の足の最初のティック）の成行。
   切断・停止の間に決済足や休場明けを過ぎた建玉は、つながったとき（起動・再接続・追いつき処理の後）の成行。市場が閉まっていて決済できなかったときは、取引が再開した最初のティックの成行。
4. **時刻**: `InpServerOffsetHours` は固定の時差で、夏時間の自動切替には対応していない。切替がブローカーと NY でずれる週は時刻ルールが1時間ずれうる
   （EA は1日1回、期待値と違えばパネルと通知で知らせる）。土日の足は換算後の時刻の曜日で捨てる。
   `_bars.csv` はサーバー時間のまま書くので、オフセットが 0 でないときは、照合ハーネスが時刻を NY+7 に戻してから土日を除いて Python を回す（`load_mt5_csv` をそのまま使うと、日曜夜の足がずれて足番号が合わない）。
5. **END 行**: Python は最後の足で残りの建玉を END で決済する。EA は停止時（OnDeinit）に同じ計算で END 行を書く。
6. **パネルの状態の分け方（表示だけ）**: パネルの ZONE は「R03〜R05 で 4H MA の傾きが OK」か R09/R10 のときに限り、R06 は WATCH として扱う（SPEC 付録E の E-18）。
   ダッシュボード用の `strategy.snapshot()` も同じ分け方にそろえてある。違うのは、パネルの IDLE が「G1 不成立」で決まるため、データの先頭付近で G1 が成立して R00（指標の準備未了）のとき、パネルは WATCH、snapshot は IDLE になることだけ。
7. **MT5 の方が良く出る方向の差**: Python は足の中の順序が分からないので SL を優先し、約定足では SL だけを判定する。MT5 のリアルティックは実際の順序で約定する（SPEC §17.11）。
8. **欠損足・薄い足**: MT5 はティックのない時間の足を作らない。Python も同じ扱いだが、祝日の薄い足で差が出ることがある（SPEC §17.12）。
9. **パターン②・①-M15（M15 を使う任意拡張）は実装していない**。入力は SPEC §12 のパラメータと任意ゲートだけで、分割・建値もありません。
   照合できる構成は fusion と任意ゲートの9つ（F+G3／F+d1／F+d1soft／F+gap／F+clear／F+clear_d1／F+support／F+slnode／F+p3）で、ほかの事前登録の変種は Python 専用。
   理由コードの R13（1H 転換型でない）と R16（目標が近い）は oku_only・kenjin_only 専用で、EA では出ない。
10. **値の動かない足（ATR=0）**: ATR14 が 0 以下の足は、EA は R00 として見送る（押しの深さ・MA 収束の窓と gap_prev からも ATR≤0 の足を除く）。
   Python は 0 割りで inf/NaN を作ったまま評価を続ける。MQL5 の 0 割りは実行時エラーで EA が止まるため、意図して残している差。
   MT5 はティックのない足を作らないので、14本続けて値が動かない足は実データでは起きない（合成データでだけ理由コードが割れ、取引は割れなかった）。

## 注意事項

- **投資助言ではありません**。過去の結果は将来の利益を保証しません。必ず通知のみ → デモ → 少額の順で進めてください。
- 既定の構成とパラメータは凍結した仕様です。**検証の結果を見てから数値を変えない**でください（変える場合は v1.1 として新しい未接触データで評価し直す。SPEC §0.2）。
- 裁量で分割・建値移動・早利確を加えると別の戦略になります（パネルの固定文言）。EA の通知を裁量の補助に使うときも、そのことを理解したうえで使ってください。
- 重要指標（FOMC・雇用統計・CPI）前後はスプレッドが広がります。自動売買ではスプレッド防御（3×s_nom 超で武装しない）が働きますが、通知のみの運用で裁量で入る場合は見送りを勧めます。
- GOLD（XAUUSD）は Good Friday が休場、感謝祭翌日・独立記念日が早仕舞いとして暦に組み込まれています。ブローカーの休場・早仕舞いが違う場合は `InpExtraClosedDays`／`InpExtraEarlyDays` で追加してください。
- 週末・休場前は建玉を全決済します。これは仕様の一部で、持ち越したい場合に合う EA ではありません。
- 端末が止まっている間は判定も決済も止まります。通知のみでも、24時間動く環境で使うことを勧めます。
- 自動売買中に EA を外す・チャートを閉じると、残った注文・建玉は管理されません（EA は停止時に知らせます）。止めるときは、先に注文・建玉を整理してください。
- 読み込んだ履歴が壊れている（足の欠け・値の変化）と、EA はそれを検出して読み込み直します。頻発する場合は履歴を再ダウンロードしてください。
