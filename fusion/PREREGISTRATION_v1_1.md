# 事前登録：FUSION-CORE v1.1 の検証（新しい未接触データで評価する）

このファイルは、v1.1 の評価を**走らせる前に**書いて固定したものです。評価は `fusion/v11_eval.py` を
このファイルどおりに実行し、結果は良くても悪くても `fusion/RESULTS_v1_1.md` にそのまま載せます。
v1.0 の最終検証は不合格でした（[RESULTS.md](RESULTS.md)）。v1.0 の仕様（`fusion/SPEC.md`、付録E を含む）は変えません。

## 1. 仮説

- **v1.1 ＝ v1.0（`fusion`）に、理由コード R13 を足したもの。**
  - R13：1時間足の持続型ダウ状態がすでにトレード方向にある（T_SMALL[t]＝d）なら見送る（SPEC §8 の R13）。
  - 言い換えると、「1時間足がまだ逆向きか中立で、これから転換するところ」だけを取る。
    100億のパターン①「1時間足が下降トレンドから上昇トレンドに**転換した瞬間**にエントリー」をそのまま条件にしたもの。
  - コードでは `fusion/strategy.py` の `VARIANTS['F+h1trans']`（`h1_transition=True`）。ほかの規則・パラメータは v1.0 と同じ。
- **選んだ経緯**
  - v1.0 の最終検証のアブレーション26変種のうち、点推定が最も高かった。
    - 平均 +0.103R（1,086回）。fusion は +0.055R。差は +0.048R（z＝0.58、Holm 調整 p＝1.0）。
  - ただし U-B（2018〜2020）では、F+h1trans 自身も −0.039R とマイナスだった。
- **事前の見込み（正直な予想）**
  - 26変種の中の最大を選んだので、新しいデータでは平均が下がる（平均への回帰）と見込む。
  - 真の平均Rは、おそらく 0〜+0.06R の間。合格の見込みは低い（§9 の検出力）。
  - それでも評価するのは、使えるかどうかを、事前に決めた手順で白黒つけるため。

## 2. データ

### 2.1 第1段（いま使えるデータ）

- **出典**：GitHub の公開リポジトリ [komo135/forex-historical-data](https://github.com/komo135/forex-historical-data)
  （コミット `e6f76e71ab8cc78d7e7e7fd9c54eb42e5cd9ed9d`）の1時間足 CSV。
  - MT5 の書き出しと見られるが、ブローカーは不明（出どころを確かめられない、という制約を結果にも書く）。
  - 12銘柄：EURUSD・GBPUSD・USDJPY・EURJPY・GBPJPY・AUDUSD・USDCAD・AUDJPY・XAUUSD・EURGBP・EURCHF・USDCHF。
  - 各銘柄 57,600本。2012-11〜2022-03-04（XAUUSD は 2012-05〜）。
- **ほかの出典を使わなかった理由**：この環境からは、histdata.com・Dukascopy・Yahoo Finance・Hugging Face・Google ドライブへの接続が
  プロキシに拒否された（2026-10-31）。届く公開データのうち、2020年6月以降の複数銘柄の1時間足はこれだけだった。
- **確かめたメタデータ**（売買の成績は計算していない）
  - 時刻の重複・四本値の矛盾・土日の足はない。
  - 週の始まりは月曜0時（486週中482週。残りは年末年始などの休場明け）、終わりは金曜22〜23時。
    よって時刻は、サーバー時間 NY＋7時間（v1.0 と同じ）とみなす。XAUUSD は月曜1時始まり（金の取引開始が1時間遅いため）。
  - 4日を超える欠けは、EURCHF の 2015-01-19 からの18日間だけ（スイス国立銀行ショック後の取引停止）。そのまま使う
    （v1.0 の休場明けフォールバック、12時間以上の窓明けで扱う）。
- **変換**
  - 価格＝生の値 ÷ 10^桁。桁は、円のペア（USDJPY・EURJPY・GBPJPY・AUDJPY）が3、XAUUSD が2、ほかは5。
  - 書き出しの価格は Bid とみなし、四本値すべてに s_nom/2 を足して仲値にする（`fusion/broker.py` は足の価格を仲値として扱うため）。
  - 時刻はそのまま使い、土日の足は除く（`fusion.data` と同じ処理）。
- **スプレッド（s_nom）**：SPEC §10.3 の表の値。表にない3銘柄は、評価の前に次の値で固定する。
  - EURGBP 0.00015、USDCHF 0.00015、EURCHF 0.00020（SPEC の表の主要ペアと同じ水準の、個人向けの標準的なスプレッド）。

### 2.2 第2段（利用者の MT5 のデータ。第1段で打ち切りにならなかったときだけ）

- 利用者の MT5 から、同じ12銘柄（ブローカーにある分）の1時間足を書き出してもらう（「表示」→「銘柄」→「チャートバー」）。
  - 期間は 2021-12-01 から書き出した日まで（2022-03-04 までの分はウォームアップにだけ使う）。
- 時刻：週の最初の足が月曜0時なら NY＋7 とみなしてそのまま使う。日曜21時か22時なら UTC とみなし、`fusion.data.utc_to_server` で変換する。
  それ以外の場合は、評価の前に利用者に確かめ、変換を決めてから実行する。
- 価格は Bid とみなし、第1段と同じく s_nom/2 を足す。銘柄名の接尾辞（EURUSD.a など）は表の名前に読み替える。
- 書き出したファイルはコミットしない。ファイル名・行数・期間を結果に書く。

## 5. 素朴ベースライン

- v1.0 の事前登録 §5 と同じ（同じループ・同じ時刻ルール・同じ出口、確率 p で次の足の始値に成行、SL＝1.5ATR）。
- 乱数：`numpy.random.default_rng(seed * 1000 + 銘柄番号)`。seed＝0〜19。銘柄番号は次の順で 0〜11。
  - EURUSD, GBPUSD, EURJPY, AUDUSD, USDCAD, AUDJPY, XAUUSD（ここまで v1.0 と同じ番号）, USDJPY, GBPJPY, EURGBP, EURCHF, USDCHF
- p の決め方：損益は見ず、回数だけで決める。p ∈ {0.005, 0.01, 0.015, 0.02, 0.03, 0.05, 0.08} のうち、
  20シードの合算取引数の平均が v1.1 の合算取引数に最も近いもの。±20% に入らなかった場合は、そのことを報告する。

## 6. 段階と打ち切り

1. **第1段（いま）**：U-X＋U-D で全構成を1回だけ走らせる。
   - **打ち切り**：v1.1 の第1段の合算平均R ≤ 0 なら、v1.1 は「不合格（第1段で打ち切り）」と記録し、第2段は行わない。
   - **継続**：合算平均R＞0 なら、第1段の値を報告する（合否は出さない）。利用者に第2段のデータを依頼する。
2. **第2段（データが届いたら1回だけ）**：U-E を加えて全構成を走らせ、第2段の合算で §8 の P1〜P6 を判定する。
   - U-X・U-D の結果は第1段と同じになるはず（同じコード・同じデータ）。違ったらその理由を調べて報告する。
   - 第2段のデータが手に入らないときは「未決」とし、自動売買は無効のままにする。

## 7. 統計の定義（v1.0 の事前登録 §6 と同じ。違うところだけ書く）

- **R・平均R・t値・月ブロック・ブートストラップ**：v1.0 と同じ（10,000回、seed=12345）。月は、合算に含まれる全月。
- **P6 の DSR**：試行回数 N＝1（SR₀＝0。Probabilistic Sharpe Ratio と同じ）とし、DSR ≥ 0.95 を求める。
  - 理由：v1.0 の P6（N＝250）は、同じ系統のデータで約250の構成を試したことへの割り引きだった。
    v1.1 は、別のデータで選んだ1つの仮説を、新しいデータで1回だけ試す。選択の偏りは新しいデータそのものが取り除くので、
    もう一度 N で割り引くのは二重の割り引きになる。歪度・尖度の補正だけを残す。
  - 系列：合算の月次R（その月の全取引の pnl_r の合計。取引のない月は0）。期間は合算の最初の月から最後の月まで。

## 8. 合格基準（第2段の合算。P1〜P6 をすべて満たしたら「合格」）

| # | 基準 |
|---|---|
| P1 | 合算の平均R＞0、t≥2.0、月ブロック・ブートストラップの95%区間の下限＞0 |
| P2 | U-X・U-D・U-E のうち2つ以上で平均R＞0。かつ、合算で30回以上取引した銘柄のうち60%以上で平均R＞0 |
| P3 | 各プールを期間の中点で前半と後半に分け、全プールの前半どうし・後半どうしを合算して、どちらも平均R＞0。中点は U-X＝2016-10-07 00:00、U-D＝2021-04-09 12:00、U-E＝2022-03-05 0時と「最後の日の翌日0時」の中間 |
| P4 | v1.1 の平均R ≥ 素朴ベースライン（20シードの平均R の平均）＋0.10R。かつ、20シードの平均R の95パーセンタイルを上回る |
| P5 | Rの上位1%の取引（ceil(0.01·n) 件）を除いても、合算平均R ≥ 0 |
| P6 | DSR（N＝1）≥ 0.95 |

**警告**（不合格ではないが、自動売買の前に解消が必要）：v1.0 と同じ（売買の片方だけがマイナス、GAP_FALLBACK が FX で年1件を超える、EURUSD の10か月あたりの回数が15回未満）。

**参考として報告するもの**（合否に使わない）：fusion（v1.0）の同じプールでの成績、v1.1 − fusion の差と標準誤差、
s_nom×1.5 での v1.1、銘柄別・プール別・年別・決済理由別。

## 9. 検出力（結果を見る前の見込み）

前提：v1.1 の1取引あたりの R の標準偏差 2.15（v1.0 の最終検証の F+h1trans）、取引の頻度 21.5回／銘柄年。

| | 銘柄年 | 取引数（見込み） | 平均Rの標準誤差 | t≥2 に要る平均R |
|---|---|---|---|---|
| 第1段（U-X 36.0＋U-D 21.7） | 57.7 | 約1,240 | 0.061 | +0.122 |
| 第2段（＋U-E。2026-10 まで書き出せた場合 55.9） | 113.6 | 約2,440 | 0.044 | +0.087 |

| 真の平均R | 第1段で打ち切りになる確率 | 第2段の P1（t≥2）を満たす確率 | 第2段の P4 を満たす確率（素朴を +0.019R とした場合） |
|---|---|---|---|
| 0 | 50% | 2% | 0.3% |
| +0.05 | 21% | 20% | 6% |
| +0.10 | 5% | 62% | 33% |
| +0.15 | 0.7% | 93% | 76% |

- 実質的な関門は P4（素朴ベースラインを 0.10R 上回る）。v1.1 に +0.10R の実力があっても、合格の確率は3割ほど。
- 不合格は「優位性がないことの証明」ではない。とくに +0.05R 前後の小さな優位性は、この量のデータでは見分けられない。

## 10. 判定後の扱い

- **第1段で打ち切り、または第2段で不合格**：v1.1 は「優位性なし」と記録する。EA の自動売買は無効のまま。
  - 同じデータで別の改良案を選び直すことはしない。次の案は、さらに新しいデータ（例：2026年11月以降の実時間のデータ）で評価する。
- **第2段で合格**：次の順に進める。どれかで止まったら、自動売買は有効にしない。
  1. EA に R13 を実装し、`mt5/engine_check` で Python との一致を確かめる（いまの EA は R13 を実装していない）。
  2. 利用者の MT5 のストラテジーテスターで U-E の期間を回し、照合ハーネスで Python と一致することを確かめる（SPEC §18 の基準）。
  3. デモ口座で3か月、通知のみで動かし、30シグナル以上で Python との一致を確かめる。
  4. そのうえで、自動売買を任意で有効にできる（risk 0.5% から）。
