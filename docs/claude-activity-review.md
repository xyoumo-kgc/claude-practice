## 2. 総評

### 良かった点（このまま続けたいところ）

- **依頼が具体的で、業務の実物に紐づいている。** 「mm 単位で」「表紙に物件名とお客様名」「境界の壁にドアを置いたら両側が抜ける」など、現場で困る粒度の指定が出ている。これは AI に対して最も費用対効果の高い依頼の仕方です。
- **段階的に積み上げている。** CAD は 7 回の PR で「図形を置ける」→「提案書として渡せる」まで到達。1 回で全部を求めず刻んだのが成功要因。
- **検証を伴っている。** Playwright での E2E 確認、PDF の構造検証、部屋の連結を座標の数値で照合、など「動いたと言い張る」で終わっていない。
- **業務の全工程に手を伸ばしている。** 設計（CAD）→ 提案（PDF）→ 集客（X 記事・動画）→ 受注（クラウドソーシング）→ 稼働管理（バーチャルオフィス）と、一社分のバリューチェーンをほぼ網羅している。

### もったいない点（ここが伸びしろ）

1. **成果物が「資産」になっていない。** ブランチに置いたままでは、次のセッションの私からは見えません。特に致命的なのが**スキル**です。`/fx-analyze` も `narration` スキルも `.claude/` 配下にありますが、**`master` に無いため新しいセッションでは呼び出せません**。せっかく型化したものが毎回ゼロからになります。
2. **リポジトリが「練習用」のまま雑居ビル化している。** CAD（TypeScript）・FX（Python/MQL5）・動画（Python）・マーケ（Markdown）が同居し、依存関係も評価軸もバラバラ。将来お客様に渡す CAD と、個人投資の EA が同じ場所にあるのはリスクでもあります。
3. **自動テストが無い。** 品質は毎回「私が Playwright を手で回して確認」に依存。`main.ts` は既に 67KB あり、次の改修でどこが壊れるか誰も分からない状態です。CI は Pages デプロイのみで、しかも**古い機能ブランチ名がトリガに残っています**。
4. **依頼が単発で、繰り返しの仕組みになっていない。** 毎回「作って」で終わり、「毎週こうする」「案件が来たらこう流す」という定常業務のパイプラインになっていない。ここが今いちばん大きな空白です。
5. **接続済みの外部ツールを使えていない。** このアカウントには **Canva / Google Drive / Zoom / Netlify** が接続済みですが、これまでの依頼では一度も使われていません。看板デザイン・納品物管理・商談議事録は、まさにこれらと直結する業務のはずです。

## 3. 提案：業務に効く仕組み（優先度順）

### レベル 0：土台を整える（今週やる価値が最も高い）

| # | 仕組み | 何が変わるか |
| --- | --- | --- |
| 0-1 | **ブランチ棚卸しと `master` 統合** | Open PR 6 本を「統合／別リポジトリへ退避／破棄」に仕分け。埋もれた 5,000 行が使える状態に戻る |
| 0-2 | **`.claude/skills/` を `master` に集約** | `/fx-analyze`、`narration` が**どのセッションからも即使える**ようになる。以後スキルは必ず `master` へ |
| 0-3 | **`CLAUDE.md` の作成** | 業種・お客様の呼び方・単位（mm）・提案書の体裁・使う技術・禁止事項を明文化。毎回の説明が不要になり、出力のブレが消える |
| 0-4 | **SessionStart フック + `settings.json` の許可リスト** | セッション開始時に `npm ci` 等を自動実行。承認プロンプトも減り、立ち上がりが数分短縮 |
| 0-5 | **CI（型チェック + Playwright E2E）を PR で自動実行** | 「壊れていないか」を人手で確認しなくてよくなる。`deploy.yml` の古いブランチトリガも同時に修正 |
| 0-6 | **リリースの仕組み（タグ + `web-cad.html` の版管理）** | お客様に配った単一 HTML が「いつ版か」を追える。不具合時に戻せる |

### レベル 1：本業（設計・提案・受注）を回す仕組み

| # | 仕組み | 内容 |
| --- | --- | --- |
| 1-1 | **`/proposal` スキル（提案書ワンストップ）** | 物件名・お客様名・要望メモを渡すと、CAD シーンの雛形 JSON + 表紙付き提案 PDF + 見積内訳の下書きまで一気に生成 |

| 1-4 | **看板デザイン量産パイプライン（Canva 連携）** | ブランドテンプレートを 1 つ作り、案件情報を差し込んで A/B/C 案を一括生成 → 提案資料へ。`kodachi-signboard` の作業がテンプレ化できる |
| 1-5 | **`/job-check` 案件応募判定スキル** | クラウドソーシング等の募集文を貼ると、対応可否・想定工数・見積レンジ・応募文ドラフトを出力。`crowdworks-job-eligibility` ブランチの狙いをスキル化 |
| 1-6 | **商談議事録 → 要件書（Zoom 連携）** | 打合せ録画から決定事項・寸法・希望色・納期を抽出し、提案書の入力データへ落とす |
| 1-7 | **納品物の自動整理（Google Drive 連携）** | 顧客／案件ごとのフォルダ規約を決め、PDF・図面・画像を所定の場所へ格納。「あの案件の図面どこ？」を撲滅 |
| 1-8 | **案件台帳（1 枚の xlsx / md）** | 引合→見積→受注→着工→納品→請求 のステータスを一元管理。週次で自動サマリ（下の 3-1 と接続） |
