## S. 金額が静かに狂う

### S-1. 商品マスタの「説明」を入れた商品は、明細に入れた瞬間に金額が消える
`1683 / 2020 / 2444 / 2518 / 2699 / 3610`

`info` が二つの意味で使われている。マスタでは「説明」の文字列、明細行では「情報行＝金額に含めない」の
真偽値。`addItem()` がマスタ行をそのままコピーするため、説明文が情報行フラグとして解釈される。

```
通常商品 10,000 ＋ 説明つき商品 50,000  →  商品計 10,000
```

編集画面の金額欄には ¥50,000 が表示されたまま（2703行は情報行でも金額を描画）なので目視で気づけない。
クイック見積・定型セット・テンプレコマンド経由でも同様。

**修正案**：明細行のフラグを `noAmt` に改名し、マスタ由来の説明は `desc` に分離。移行コードで
`info===true → noAmt` / 文字列 `→ desc`。情報行の金額欄は「—」表示に。

### S-2. 法定福利費・現場諸経費が「割引前」の金額に掛かっている
`2496-2515 / 2373-2393`

割引行が区間をリセットするため、直後の諸経費は `prevAuto`（＝割引対象の定価リスト）にフォールバックする。
「⚡諸経費を自動挿入」は各工事区分の末尾＝割引より後に入れるので、この経路にほぼ必ず入る。

```
商品 100,000 / 割引 30% / 法定福利費 15%
対象ベース 100,000 → 諸経費 15,000
割引後 70,000 基準なら 10,500（差 4,500）
```

**どちらが正しいかは積算ルール次第。要判断。**

**修正案**：諸経費行に `base:'gross'|'net'` を持たせ「割引前／割引後」の切替を出す。既存見積は
`gross` 固定で読み込み、新規の既定だけ変更。

### S-3. 「見積全体」の現場管理費が、いちばん最後の一式行に吸い込まれる
`2525-2536 / 2232-2248`

一式行の金額は「次の一式行／工事区分まで」を合算する。「諸経費を自動挿入」は現場管理費を明細末尾に
置くため、直前の一式ブロックに入る。

```
A区分 一式A（子 100,000） / B区分 一式B（子 200,000） / 現場管理費 5%(全体) = 15,000
→ 一式A 100,000 / 一式B 215,000（B区分の計に全額）
```

総額は合うが区分別金額と一式行金額が誤る。さらに請求書・契約書の `summaryTable` は各区分へ按分して
いるため、**見積書と請求書で区分別金額が食い違う**。

**修正案**：全体スコープの諸経費は一式行合計・工事区分計から除外して独立行にする。または画面側も
請求書と同じ按分に統一。

### S-4. 一式行に「大分類」が無いとカテゴリ割引が黙って0円になる
`2444-2445 / 4707-4714`

コメントは「なければ工事区分名で代用」だが実装は `cat:e.cat||''` のみ。補完役の `migratePkgCat` は
工事区分名がカテゴリ名と完全一致するときしか効かず、「1F 内装工事」のような実運用名では空のまま。

```
工事区分「1F 内装工事」/ 一式行（大分類なし）50,000 / 割引 30%
→ 対象 ¥0（0件）、割引額 ¥0（率だけ表示される）
```

**修正案**：提出前チェックで「一式行の大分類が未設定」「対象0件の割引行」を要修正（赤）に格上げ。
一式行追加時に工事区分名から候補を初期選択。

### S-5. 一式行の表示金額だけ1円丸めを通っていない
`2534`

集計は `amtOf()`（四捨五入）、表示 `own` は生の掛け算。単価 1,000.4 × 3 → 表示 3,001.2 / 集計 3,001。

**修正案**：`own` も `amtOf()` に置き換え（1行）。

### S-6. 割引マスタを直すと、既存明細が「未選択に見えるのに引かれ続ける」
`2355-2359 / 3242`

明細の割引行は `ラベル|カテゴリ|率|対象商品` の文字列まるごとを鍵にしている。割引名を1文字直す・率を
変える・マスタ配信で置き換わる、いずれでも既存行はどの選択肢とも一致せず「割引を選択…」と表示される。
**それでも旧レートでの値引きは効いたまま。**「消えたと思って選び直す → 二重に引かれる」事故に直結。

**修正案**：割引マスタに不変IDを持たせ、明細は `discId` ＋当時の名称・率のスナップショットを保持。
マスタと差がある行には「マスタ変更あり」の印。

### S-7. 対象商品名にカンマが入ると割引が過剰マッチする
`2955`

対象商品を1つの文字列に詰めて `,` `、` で分割している。マスタには商品名にカンマを含む行が12件、
カテゴリ名にもカンマが4種。

```
「1段1基　幅：1,500㎜㎜×奥行：1,800㎜」
→ ["1段1基　幅：1", "500㎜㎜×奥行：1", "800㎜"]
   部分一致なので "1" を含む商品すべてが割引対象になる
```

**修正案**：対象商品を配列 `items:[]` で保持。移行時は分割したうえで選び直しを促す。

### S-8. 別の見積を開いたあと Ctrl+Z で前の見積が復活する
`5150-5185 / 2810 / 2849 / 2856`

`_hist` は起動時に1回だけ初期化され、新規作成・見積を開く・複製のいずれでもリセットされない。
`restoreHist()` は保存JSONをそのまま `cur` に戻すため `id` ごと前の見積に化ける。その状態で保存すると
**前の見積が上書きされる**。マウスの戻るボタンにもアンドゥが割り当たっている（5202行）ため誤爆しやすい。

**修正案**：`newQuote / loadQuote / dupQuote` の末尾で
`_hist=[JSON.stringify(cur)]; _hptr=0; updateUndoBtns();`

### S-9. 一部の破壊的操作がアンドゥで戻せない
`2747 resetEst / 4271 applyArea / 1726 editTcmdContent`

行の削除・並べ替えは `snapshotNow()` を呼ぶが、「明細クリア」「面積一括反映」「テンプレの内容を編集」は
呼んでいない。直前に文字入力が無ければ戻せない。

**修正案**：3箇所の先頭に `snapshotNow()` を追加。

## 着手順の提案

1. **S-1 と S-8**：「気づけないまま金額が消える」「気づけないまま別の見積を上書きする」ため最優先。
   修正自体は小さく、S-8 は3行。
2. **S-2 の方針決め**：諸経費を割引前／割引後どちらで積むか、実務の答えが要る。**ここだけは要判断。**
3. **S-3 / S-4 / S-5 / S-9 ＋ A-1 / A-2 / A-4 / A-10**：計算と帳票の整合。あわせて自己テスト（C-6）に
   S-1〜S-9 の回帰テストを追加し、再発しない状態にする。
4. **B-5 / B-6 / B-7 / B-3 / B-2**：日付ずれ、ロック漏れ、画像で容量が飛ぶ問題。独立していてまとめて直せる。
5. **S-6 / S-7 / B-13 ＋ D群**：割引・商品マスタに不変IDを入れる構造変更。データ移行が伴うのでバックアップ後に。
   ここでマスタの棚卸しも実施。
6. **A-3 / A-6 / A-7 / A-8**：帳票の日付・番号の独立、契約書の法定記載事項、税率の外出し。A-6 は法務確認が前提。
7. **C-4**：マスタをHTMLから外に出す。いちばん効くがいちばん大きい変更。上が片付いてから。
